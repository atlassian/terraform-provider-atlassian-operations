# atlassian-operations Provider



## Example Usage

With a classic API token:

```terraform
terraform {
  required_providers {
    atlassian-operations = {
      source = "atlassian/atlassian-operations"
    }
  }
}

provider "atlassian-operations" {
  cloud_id      = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  domain_name   = "xxxx.atlassian.net"
  email_address = "email@example.com"
  token         = "<YOUR_TOKEN_HERE>"
}
```

## Authentication

The provider authenticates with an email address and an API token:

* **Classic API token** (default): the configuration above.
* **Scoped API token** of a user or a **service account**: set `is_scoped_token = true`
  (or `ATLASSIAN_OPS_IS_SCOPED_TOKEN=true`). Teams are then managed through the Teams GraphQL API and users are
  looked up through `api.atlassian.com/ex/jira/{cloud_id}`; everything else is unchanged.

```terraform
# A service account's scoped API token
provider "atlassian-operations" {
  cloud_id        = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  domain_name     = "xxxx.atlassian.net"
  email_address   = "my-bot@serviceaccount.atlassian.com"
  token           = "<SERVICE_ACCOUNT_SCOPED_API_TOKEN>"
  is_scoped_token = true
}
```

The token scopes, service account requirements and limitations are described in the
[Scoped API Tokens and Service Accounts](https://registry.terraform.io/providers/atlassian/atlassian-operations/latest/docs/guides/scoped-api-tokens-and-service-accounts) guide.

## Schema

### Optional

- `api_retry_count` (Number) The number of times to retry failed API requests. Defaults to 3.
- `api_retry_wait` (Number) The initial wait time in seconds between API retries. This value is doubled for each subsequent retry. Defaults to 1.
- `api_retry_wait_max` (Number) The maximum wait time in seconds between API retries. Defaults to 30.
- `cloud_id` (String) The unique identifier of your Atlassian Cloud instance. This can be found in your Atlassian Cloud URL.
- `domain_name` (String) The domain name of your Atlassian Cloud instance (e.g., 'your-domain.atlassian.net').
- `email_address` (String) The email address of the Atlassian account the token belongs to: an admin user, or a service account (`...@serviceaccount.atlassian.com`).
- `is_scoped_token` (Boolean) Set to true when `token` is a scoped API token. The Teams REST API does not accept scoped tokens, so teams are then managed through the Atlassian GraphQL Gateway, and Jira user lookups go through api.atlassian.com/ex/jira/{cloud_id}. Defaults to false (classic API token). Can also be set via the ATLASSIAN_OPS_IS_SCOPED_TOKEN environment variable. The required token scopes are listed in the Scoped API Tokens and Service Accounts guide.
- `org_admin_token` (String, Sensitive) The API token of the organization admin, to be able to use User APIs. This field is only required & used for Compass.
- `product_type` (String) The type of Atlassian Operations product you are using. This can be 'jira-service-desk' or 'compass'. Defaults to 'jira-service-desk'.
- `token` (String, Sensitive) Your Atlassian API token: a classic API token from your Atlassian account settings, or a scoped API token of a user or service account (then also set `is_scoped_token = true`).
